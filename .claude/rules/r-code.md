## R Code

- **Never** use the `.data$` pronoun in tidyselect contexts (`select()`, `rename()`, `relocate()`, `across(.cols=)`, `pivot_wider(names_from=)` / `pivot_longer(cols=)`, `unnest_wider(col=)`, gt column-selection arguments). Use string column names (`"col"`), bare names, or tidyselect helpers (`all_of()`, `any_of()`, `starts_with()`, `where()`, etc.) instead. `.data$col` is correct **only** in data-masking contexts (`mutate()`, `filter()`, `summarise()`, `arrange()`, `if_else()`, `case_when()`, `aes()`). *(R-specific)*
- **Always** namespace-qualify calls to functions from non-`base` packages with `pkg::fn(...)`, even when `pkg` is a recommended package auto-attached at R startup (`stats`, `utils`, `methods`, `grDevices`, `graphics`, `datasets`). The alternative is an explicit `#' @importFrom pkg fn` in roxygen plus a corresponding entry in `DESCRIPTION` `Imports`. Auto-attachment populates the interactive search path, but `R CMD check` codetools resolves package code against `base` + declared imports only — unqualified non-`base` calls produce *"no visible global function definition"* NOTEs. Documentation links (`[pkg::fn()]` in roxygen) and in-message references inside backticks (e.g. `` `stats::rbinom()` `` in an error message) stay as-is — they're documentation, not calls. Authoritative source: *Writing R Extensions* §1.1.3 / §1.6. *(R-specific)*
- **Never** build a loop or index sequence as `1:n` (`1:length(x)`, `1:nrow(df)`, `seq(n)`). When `n` is 0 it yields `c(1, 0)`, so the body runs on elements that do not exist and fails far from the cause, or quietly produces wrong output. Iterate with `seq_along(x)` or `seq_len(n)`, or loop over the elements or names themselves. Where an empty input can never legitimately reach the loop, do not leave it to the loop: check first and `rlang::abort()` with a message that says what was expected and what arrived. *(R-specific)*
- **Always** raise an error with `rlang::abort()`, never with `stop()` or `stopifnot()`. `abort()` names the calling function in its header, renders a message vector as a headline with `i` / `x` bullets, and takes a `class` that a caller or a test can match without parsing text, where `stop("…")` and `stopifnot()` raise an unclassed `simpleError`. `abort()` does not paste several arguments together the way `stop()` does, so build a message from parts with `paste0()` or `sprintf()`. To re-raise a condition caught in a handler, use `rlang::cnd_signal(cnd)`, which keeps its class and message. *(R-specific)*
- **Always** raise a warning with `rlang::warn()`, never with `warning()`, for the same reasons: a `class` a caller can match or muffle without parsing text, and bullets for context. Build a message from parts with `paste0()` or `sprintf()`, as for `abort()`. An `rlang::warn()` condition is a `warning` like any other, so a caller's handlers catch it exactly as they caught a `warning()`. *(R-specific)*

### Joining tibbles

- **Never** join tibbles on DHIS2 UIDs (`trackedEntity`, `enrollment`, `event`, `orgUnit`, `country`, `programStage`, `dataElement`, etc.) when both sides already carry synthesized integer keys (`patient_key`, `enrollment_key`, `event_key`, `department_key`, `hospital_key`, `country_key`, etc.). Always join on the integer keys. The only exception is during import when at least one side of the join doesn't have an integer key yet (raw API response → keyed tibble bridge via an internal map like `.patients_internal_map`). DHIS2 UIDs are opaque artefacts for linking back to DHIS2; integer keys are the relational backbone.
